# 真实社区 A/B 对比测试报告｜运行说明与待实测模板

> **本文件故意不预填任何真实社区结果。** 未配置参赛者自己的百度地图 AK 时，不允许用离线模拟数据替代“真实对比测试”。

## 1. 已提供自动化脚本

项目已经把“选点、地理编码、统一参数分析、汇总报告”自动化：

```bash
python scripts/run_real_benchmark.py
```

默认测试定义在：

```text
scripts/benchmark_cases.example.json
```

当前默认两个地址只是便于一键复现实测的上海样例：

- 上海市浦东新区张江镇人民政府
- 上海市徐汇区徐家汇街道办事处

脚本会在运行时调用百度地理编码，**项目并未预先硬编码或声称这些地址的坐标。**

## 2. 成功后自动生成

```text
docs/真实对比测试报告_自动生成.md
docs/真实对比测试报告_自动生成.json
```

报告包含：

- BD09 坐标
- 等时圈面积
- 体检分（如数据完整）
- 数据置信度
- 盲区点
- HTTP 请求数
- RouteMatrix 等配额单元估算
- 总耗时
- 各设施覆盖
- 直线圆 vs 路网可达差异
- 警告/待核验

## 3. 建议正式提交时再补的人工证据

对两个样例分别保存：

- 浏览器整页截图
- 等时圈 + POI + 盲区图
- 百度静态地图快照
- Markdown/HTML 报告
- JSON 原始结果
- GeoJSON
- API 统计区截图

## 4. 对比结论写法

只写真实数据能支持的结论。例如：

- A 的路网面积明显小于直线圆，且绕行系数更高；
- B 的药店/小学覆盖更完整；
- 某区域存在多类别叠加盲区；
- 某类别因 API 异常而为未知，不能据此判断缺失。

不要写未经验证的人口需求、政府规划缺口或“必须新增某设施”等确定性政策结论。

## 5. 实测前检查

```bash
python scripts/check_baidu_api.py
```

确认地理编码、Place、RouteMatrix、DirectionLite 均可用后，再跑完整 A/B benchmark，以减少不必要配额消耗。
