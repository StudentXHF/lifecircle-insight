## 二、仍然真实存在的限制

1. **等时圈是离散路网测时后的空间插值近似**，不是持有底层路网拓扑后的洪泛等时面。
2. POI 召回受百度地图数据质量、关键词、权限和配额影响。
3. 设施数量不等于设施容量、质量、人口需求或服务等级。
4. 当前盲区以离散采样点为主，尚未聚类成官方规划意义的连续缺口面。
5. “真实城市 3D”基于百度 JSAPI GL WebGL；三维楼块/精模的丰富度依赖目标区域的百度数据覆盖、缩放级别和浏览器 GPU，不能保证所有上海社区都呈现同等高楼效果。
6. Canvas 数字孪生是增强表达层，不是实际 BIM、地籍、倾斜摄影或实景重建。
7. 未接入人口栅格、街道法定边界、设施容量、无障碍网络和用地约束。
8. 当前交付环境没有参赛者百度 AK，因此不能声称真实百度 API 端到端、真实三维底图和真实 A/B 已通过。
9. Windows 离线回归已完成；真实模式仍需用户 AK 才能回归。

## 三、为什么当前没有强制引入 JSAPI Three

百度 JSAPI Three 可以进一步提供 Three.js 三维场景、楼块、精模、倾斜摄影和环境效果，但会引入额外 NPM / Three.js 构建链和新的真实三维数据依赖。

提交候选版优先保证：

- Python 单环境可快速复现；
- 真实百度 WebGL 城市底图；
- 地图 API 深度调用和空间算法评分点；
- 真实社区结果可复核。

因此 v3.0 将 JSAPI Three 留作增强路线，而不是在提交前为了视觉效果牺牲稳定性。当前 JSAPI GL 已在张江镇真实记录上完成浏览器验收；若其他区域三维建筑覆盖不足，可再评估独立演示分支，不影响主分析流程。

## 四、正式提交前最高优先级事项

1. 用户本地配置真实 `BAIDU_MAP_AK` 和 `BAIDU_MAP_BROWSER_AK`，通过 `scripts/check_baidu_api.py`。
2. 选择三维覆盖较好且具有对比性的两个上海真实社区，跑同参数 A/B。
3. 人工核验 POI、代表路线、等时圈和盲区是否与真实地图视觉一致。
4. 记录真实分析日期、参数、耗时、API 状态和关键截图。
5. 真实数值已经写入正式作品介绍、技术报告和真实对比报告；后续只在数据口径变化时更新。
6. 上传公开 GitHub/Gitee，确认 CI 且没有 `.env` / AK。
7. 录制真实演示视频并上传可公开播放链接。
8. 按提交当日官网和组委会邮件核对材料字段、命名和截止。
