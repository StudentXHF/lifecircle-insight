## 2. 采样设计

默认方位角数量 `B=16`，角度为：

```text
0°, 22.5°, 45°, ... , 337.5°
```

每个方向设置半径：

```text
500, 900, 1300, 1700 m
```

总路线数为 `16 × 4 = 64`。

这些点是“查询探针”，不是假设可达边界。真实边界完全由 RouteMatrix 返回的步行耗时决定。

## 3. RouteMatrix 批处理

步行 RouteMatrix 单次起终点组合上限为 50。因此默认 64 条路线自动拆为：

```text
批次 1：50 条
批次 2：14 条
```

工程统计同时记录：

- HTTP request count：网络请求次数。
- quota units estimated：按最终路线数估算的配额单元。

这样既能证明“批处理减少 HTTP 往返”，也不会误称“64 条路线只消耗 2 个配额”。

## 4. 等时圈阈值求解

目标阈值：

```text
T = threshold_minutes × 60
```

默认 `T=900s`。

### 4.1 非单调问题

真实 API 的半径与耗时不保证严格单调：不同样点可能绑到不同道路入口，900m 样点甚至偶尔比 500m 更快。若直接在原始耗时上插值，会产生几何尖刺或错误反转。

对每个方位按半径排序后构造保守累计最大耗时：

```text
t'_i = max(t_1, t_2, ..., t_i)
```

原始数据仍保留用于证据，`monotonic_corrections` 记录纠正次数。

### 4.2 阈值插值

找到满足：

```text
t_low <= T <= t_high
```

的相邻样本，边界半径：

```text
r* = r_low + (T - t_low) / (t_high - t_low) * (r_high - r_low)
```

如果全部样本都在阈值内，则边界受最大探测半径限制，记为 `truncated_bearings`；如果最近样点已超过阈值，则进行有限内侧估计，记为 `extrapolated_bearings`。这些诊断全部返回前端和结构化结果。

## 5. 等时圈可靠性门槛

若 RouteMatrix 有效样本比例低于 80%，主分析失败，不构造“看起来正常”的假边界。

若有效方位不足，则同样终止。

## 6. POI 检索与清洗

六类设施：

- 基础医疗
- 小学
- 菜市场
- 药店
- 超市/购物
- 养老服务

每类采用 Place 圆形检索，`radius_limit=true`，默认最多读取 3 页，每页最多 20 条。

去重键包含：

```text
类别 + UID（如有） + 名称 + 六位坐标
```

这是同一平台多类别查询的标准化去重；当前没有把外部第三方 POI 混入，避免来源许可和坐标体系不一致。

## 7. 数据缺失语义

这是 v2.0 的重要工程改进。

若“药店”请求失败：

```text
药店.status = unknown
```

而不是：

```text
药店.count = 0
```

体检分只在成功获得的类别权重上归一化。若菜市场/药店/小学任一关键类别未知，盲区模块不会声明某位置“缺少该设施”，而是返回“数据不足，待核验”。

## 8. 盲区算法

在中心点 1 km 范围按约 300m 网格采样，只保留落在等时圈内的网格点。

对每个网格点计算与关键 POI 的大圆距离，若其 1 km 内没有：

- 菜市场，或
- 药店，或
- 小学

则作为服务盲区采样点，`severity` 为缺失类别数量。

该结果是“灰色区域”的离散证据。项目没有伪称这些点已经形成政府意义上的正式规划面。

## 9. 路网与直线基线对比

为突出赛题痛点，项目额外计算：

- 直线步行假设半径：`T × baseline_speed`。
- 直线圆面积。
- 等时圈 / 直线圆面积比。
- RouteMatrix 路径距离 / 直线距离的中位绕行系数。
- RouteMatrix 时间 / 直线速度理论时间的中位时间惩罚系数。

默认直线速度 1.2 m/s，仅用于“方法比较”，不是官方标准。

## 10. 数据置信度

置信度不是“结论准确率”，而是本次分析的数据完整度提示：

```text
55% × RouteMatrix 有效样本率
+ 45% × 已成功获取的设施类别权重占比
```

它帮助评委/用户一眼识别“结果完整”还是“存在 API 类别缺失”。

## 11. 缓存与容错

- HTTP timeout
- 并发信号量
- 有界指数退避重试
- 进程内内存缓存
- SQLite TTL 持久缓存
- API cache key 不含 AK
- mock 测试时禁用持久缓存，保证测试隔离

缓存只复用相同参数的 GET 结果，不改变分析算法。

## 12. 可视化

项目提供三种互补视图：百度 JSAPI GL WebGL 真实城市底图、Canvas 数字孪生表达和本地 SVG 分析热力图。离线模式不伪造百度底图，仍可显示：

- 采样热力
- 等时圈边界
- POI
- 盲区
- 覆盖条形图
- 路网差异指标
- 算法质量指标

真实模式还可以由后端代理百度 Static Image，避免将服务端 AK 直接放进前端 URL。浏览器地图仅在页签可见后初始化；切换分析时销毁旧 WebGL 上下文，页面隐藏时停止自动环绕，SDK/AK/Referer 失败会显示明确诊断而不是空白容器。

## 13. 输出格式

- Markdown：人类可读报告。
- HTML：无需服务端即可打开的独立报告。
- CSV：POI/盲区表，带 UTF-8 BOM 和公式注入防护。
- JSON：完整结构化结果。
- GeoJSON：等时圈 Polygon + POI/盲区 Feature。
- ZIP：以上成果打包。

## 14. 算法边界

等时圈是近似区域，不是底层路网全量图搜索。设施“数量”也不代表容量或服务质量。正式规划应用仍需人口、设施容量、用地、政策、现场调查等更多数据。
