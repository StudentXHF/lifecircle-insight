# 真实城市 3D、数字孪生表达与分析热力图

版本：v3.0.0-rc3

## 1. 为什么分成三层

圈析智图不把“视觉效果”和“数据真实性”混为一谈。

### A. 真实城市 3D

来源：百度 JSAPI GL WebGL，采用官方异步回调加载方式。

用途：

- 展示真实城市道路与底图；
- 高缩放 + 倾斜 + 旋转体现空间距离感；
- 叠加 15min 等时圈；
- 叠加 500m / 1km 参考圈；
- 叠加 POI、盲区和路网探针；
- 自动环绕、路况、卫星底图。

配置：

```env
BAIDU_MAP_BROWSER_AK=浏览器端AK
BAIDU_MAP_STYLE_ID=可选个性化地图样式ID
```

`BAIDU_MAP_BROWSER_AK` 必须与服务端 `BAIDU_MAP_AK` 分开创建，并配置 Referer 白名单。

> 三维楼块 / 精模显示效果取决于百度地图在目标区域的数据覆盖、缩放级别和浏览器 GPU 能力。项目不保证每个社区都出现同等精细的高楼模型。

### B. 数字孪生表达

来源：Canvas 根据分析结果生成。

用途：无浏览器地图 AK 时仍能展示空间关系，适合离线演示与容灾。

其中楼体、树木和道路是**增强表达层**，不是实际 BIM、地籍楼块或实景重建。

### C. 分析热力图

来源：确定性分析数据。

用途：解释算法、样本、边界、POI 和盲区，是技术答辩的证据视图。

---

## 2. 为什么最终答辩应优先展示“真实城市 3D”

视觉顺序建议：

1. 真实城市 3D 作为第一眼钩子；
2. 迅速切到热力图解释算法；
3. 再切覆盖 / 盲区 / API 证据；
4. 最后导出成果。

不要长时间只展示 3D，否则评委可能认为项目重点是地图皮肤而不是路网计算。

---

## 3. 推荐视角

项目默认：

- zoom：18 左右
- tilt：72°
- heading：32°

如目标区域建筑不明显，可以在答辩前：

- 选择三维覆盖更好的社区中心点；
- zoom 调整到 18~19；
- tilt 65~73；
- heading 20~60；
- 配置个性化地图 Style ID。

这些参数只影响展示，不改变等时圈算法。

---

## 4. 距离感设计

真实地图额外叠加：

- 500 m 蓝色参考圈；
- 1 km 橙色参考圈；
- 15min 真实路网等时圈。

这样评委可以同时理解：

- 几何距离；
- 命题 1 km 盲区阈值；
- 实际时间可达边界。

数字孪生表达也绘制扇形采样距离环，避免所有楼体挤在中心。

---

## 5. 沉浸演示模式

结果页点击“进入沉浸演示”后：

- 隐藏表单、侧栏和次要模块；
- 空间可视化主舞台占满屏幕；
- 更适合录屏和现场演示；
- `Esc` 可退出。

沉浸模式不改变任何分析数据。

## 5.1 生命周期与性能保护

- 真实地图页签可见后再初始化，避免隐藏容器尺寸为零导致白屏；
- 相同分析结果复用地图实例，新分析前销毁旧 WebGL 上下文；
- 离开真实地图页签或浏览器进入后台时自动停止环绕；
- 地图 SDK、AK、Referer 或 WebGL 初始化失败时显示可操作错误提示；
- zoom 根据本次等时圈半径在社区尺度内自适应，tilt 会受当前地图允许的最大倾角约束。

---

## 6. JSAPI Three 是否使用

百度另有基于 Three.js 的 JSAPI Three，可进一步支持三维楼块、精模、倾斜摄影、天气和环境渲染。

当前参赛版本没有把它作为强依赖，原因是：

1. 会引入新的 NPM / Three.js 构建链；
2. 当前赛题核心评分是地图 API、等时圈、盲区和工程质量；
3. JSAPI GL 已能提供真实 WebGL 城市视图；
4. 保持 Windows `start.bat` 单 Python 环境更利于评审快速复现。

后续路线图可将 JSAPI Three 作为增强方向，而不是在提交前为了视觉炫技牺牲稳定性。
