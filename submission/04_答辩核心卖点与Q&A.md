# 圈析智图｜答辩核心卖点与评委 Q&A

## 一、30 秒开场钩子

> 如果直接用 1 公里圆代表 15 分钟生活圈，河道、围墙、道路绕行都会被忽略。圈析智图不自己猜道路，而是把百度地图真实步行 API 当成路网计算引擎，用多方向测时和空间插值生成 15 分钟等时圈，再检查医疗、学校、菜市场、药店等设施覆盖与 1 公里服务盲区。它既有真实城市 WebGL 可视化，也能把每次分析导出成可复核的 JSON、GeoJSON 和报告。

## 二、90 秒电梯陈述

> 圈析智图解决的是“15 分钟生活圈到底是不是实际可达”的问题。传统方案最常见的做法是以中心点画一个固定半径圆，但真实城市里有道路绕行、围墙、河道、桥梁和不同入口，所以几何距离和真实步行时间并不等价。
>
> 我们没有下载底层路网，而是通过百度 RouteMatrix 在中心点周边做多方向、多半径步行测时，再通过质量控制、单调包络和阈值插值得到近似 15 分钟等时圈。随后检索六类民生 POI，统计可达覆盖，并按照任务书要求识别 1 公里内缺少菜市场、药店或小学的服务盲区。
>
> 系统特别强调可靠性：API 失败会标记 unknown，不会误判为现实设施缺失；HTTP 批量优化和配额单元分开统计；所有算法修正都公开可见。结果既能在百度 WebGL 真实城市 3D 里展示，也能导出 Markdown、HTML、CSV、JSON、GeoJSON 和 ZIP。
>
> 项目采用 MIT 开源，FastAPI + SQLite 即可本地运行，提供 Docker、pytest 和 CI。我们的目标不是做一张更漂亮的地图，而是做一个可运行、可复核、可复现的社区生活圈体检工具。

## 三、五个最重要的答辩卖点

### 卖点 1：不是直线圆，而是真实步行时间

**一句话：** 用真实路网 API 的“时间”替代几何距离。

证据：RouteMatrix 探针、15min 等时圈、直线圆对比指标。

### 卖点 2：不拿地图 API 当截图服务，而是深度参与计算

百度能力参与：坐标、Place、RouteMatrix、DirectionLite、静态地图、JSAPI GL WebGL。

### 卖点 3：工程可靠性比“全字段填满”更重要

API 失败 -> unknown；关键路网不足 -> 拒绝生成假边界；有数据置信度和质量诊断。

### 卖点 4：可视化有层次且不造假

- 真实城市 3D：真实百度底图；
- 数字孪生表达：离线增强；
- 热力图：解释算法。

主动说明哪部分是真实数据，哪部分是表达层。

### 卖点 5：开源项目不是 Demo 文件夹

有 MIT、CI、Docker、测试、治理、安全文档、发布前密钥检查、结构化导出和真实 benchmark 脚本。

## 五、评委高概率问题与回答

### Q1：为什么不直接用地图 SDK 自带的等时圈？

**答：** 本项目希望显式展示命题要求的“地图 API 深度调用 + 空间插值”过程，因此采用 RouteMatrix 多点真实测时，把路网能力当作可调用函数，再自行构造近似等时边界。这样每个采样点、耗时和质量指标都可以解释和复核。

### Q2：这个等时圈是不是精确的？

**答：** 不是底层道路拓扑洪泛意义上的精确等时面，而是离散真实测时后的空间插值近似。我们明确标注这一边界，并提供有效样本率、单调修正、截断和外推诊断；通过增加采样方向可以提高空间分辨率。

### Q3：为什么出现“unknown”？是不是系统能力不够？

**答：** unknown 是刻意设计的可靠性语义。如果药店 API 因限流失败，把它当成 0 家会产生比“暂时不知道”更危险的规划误导。我们宁可降低数据置信度，也不制造确定性结论。

### Q4：你们所谓 3D 是真的还是假的？

**答：** 分两层。真实城市 3D 使用百度 JSAPI GL WebGL 真实底图，建筑表现取决于百度该区域数据覆盖；离线数字孪生表达层是由本次分析结果生成的展示层，我们明确标注它不是 BIM / 地籍楼块。不会把模拟建筑说成真实建筑。

### Q5：为什么不直接上 Cesium / 自己做三维城市？

**答：** 本赛题核心是百度地图开放能力和生活圈计算，不是三维引擎竞赛。我们选择 JSAPI GL 直接使用真实百度城市底图，避免为视觉效果引入大体量 3D 数据和新的部署链，同时保留未来接入 JSAPI Three / 倾斜摄影的扩展空间。

### Q6：批量 RouteMatrix 只请求两次，是不是只花两次配额？

**答：** 不是。两次指 HTTP 往返，配额通常按最终路线单元计算。因此系统把 `request_count` 和 `quota_units_estimated` 分开显示，避免误导。

### Q7：为什么盲区用 1 km，不直接用 15 分钟？

**答：** 这是命题任务书明确给出的关键盲区判定口径。系统先把候选点限制在 15 分钟等时圈内，再按 1 km 关键设施邻近规则检查，既保留赛题口径，又保持整体逻辑一致。

### Q8：POI 有重复怎么办？

**答：** 多页读取后优先按 UID 去重，并补充名称 + 坐标规则；内部统一坐标体系。

### Q9：真实使用时 API 成本和速度怎么控制？

**答：** RouteMatrix 批量、POI 有界并发、内存 + SQLite TTL 缓存、最大分析时间、最大页数和最大采样方向都可配置。正式生产可以结合实际 QPS 做参数化调优。

### Q10：AI 工具赛道里，你们为什么没有硬塞大模型？

**答：** 核心地图事实必须可验证，不能让大模型臆测道路和设施。当前版本让地图 API + 确定性空间算法负责核心判断；LLM 只接收后端筛选后的分数、覆盖、盲区、质量诊断和确定性建议，用于生成自然语言规划解读。它不接收 AK、坐标和 POI 名称，也不能改写核心事实；模型不可用时主流程照常运行。

### Q11：商业 / 应用价值是什么？

**答：** 社区和规划团队不需要部署复杂 GIS 路网即可做快速初筛；学校课程、城市更新调研、公共服务选址也可直接使用。它把一次人工地图调查压缩成标准化、可导出的流程。

### Q12：下一步最值得做什么？

**答：** 三个方向：引入口径统一的人口 / 设施容量数据；提高时段性与无障碍可达分析；接入 JSAPI Three 或政务三维数据做更完整的城市数字孪生展示。

### Q13：为什么固定半径圆不够？

**答：** 圆只表达欧氏距离，无法反映河道、围墙、桥梁、道路入口和绕行。系统仍保留直线圆作为基线，但最终边界由真实步行耗时探针决定，并直接给出等时圈面积与圆面积之比。

### Q14：为什么不下载路网后跑 Dijkstra？

**答：** 命题强调百度地图开放能力，平台步行算路还能纳入可步行性、路口和平台更新后的路网规则。我们用 API 结果构造可解释的近似边界，避免另建一套来源和许可均需维护的路网；代价是边界属于采样插值近似，我们对此明确披露。

### Q15：真实耗时为什么可能不随距离单调增加？

**答：** 不同探针可能落在道路两侧、封闭小区或跨河位置，API 误差与入口差异也会造成局部非单调。系统对同一方向使用保守单调包络，并记录修正次数，不用异常点制造过度乐观的边界。

### Q16：900 秒边界的插值依据是什么？

**答：** 在每个方向上找到包住 900 秒的相邻有效样本，在距离—耗时之间线性插值；若样本不足则明确记录截断或受控外推。它是一种可审计、计算成本可控的工程近似，不宣称连续路网精确解。

### Q17：如何证明结果不是伪造的？

**答：** 真实结果带 `LIVE_BAIDU_MAP_API` 标识，并保留中心坐标、每个方向的测时样本、API 调用统计、数据置信度、生成时间和结构化导出。离线数据固定标记 `SIMULATED_OFFLINE_DATA`；真实 A/B 由脚本现场生成 Markdown、JSON、CSV 三份相互核对的证据。

### Q18：数据多久更新一次？

**答：** POI 和路线事实来自运行时百度 API；缓存只在配置的 TTL 内复用以减少配额和等待。报告记录生成时间，因此结论对应一次分析快照，不把历史结果描述为永久实时。

### Q19：最核心的目标用户是谁？

**答：** 首要用户是街道、社区营造、城市更新与规划前期调研人员，其次是高校教学和公共服务选址团队。产品定位是低门槛初筛与沟通工具，而非替代法定规划平台。

### Q20：怎么真正落地到社区规划？

**答：** 先用等时圈和盲区筛出候选片区，再叠加人口、用地、设施容量、租赁成本和现场踏勘，形成新增、共享或搬迁设施的候选清单。圈析智图负责把第一轮空间排查标准化并导出，而不是直接作审批结论。

### Q21：它和直接打开百度地图有什么区别？

**答：** 普通地图擅长单次搜索和单条路线；本工具把多方向批量测时、六类设施覆盖、盲区识别、可靠性语义、A/B 对比和多格式交付串成一次可重复的体检流程，并公开算法与诊断证据。

### Q22：开源的实际价值是什么？

**答：** 评分口径、关键词、目标数量、采样密度和缓存策略都可审查、复现和二次开发；社区或高校能在自己的 AK 与数据条件下部署，不被一份不可验证的演示结果绑定。MIT 许可也降低了教学与原型复用门槛。

## 七、现场 API 出问题时的容灾话术

> “为了保证评审能够区分真实数据和演示数据，我们没有在 API 失败时自动伪造结果。当前网络异常时可以切换到明确标注的离线样例，演示完整算法和交付流程；真实社区结果已经提前保存于提交报告和录屏中，可供核验。”

这比现场硬说“网络没问题”更可靠。
