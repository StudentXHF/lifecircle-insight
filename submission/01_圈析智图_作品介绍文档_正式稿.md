## 1. 一句话介绍

**圈析智图**把传统“以中心点画固定半径圆”的生活圈评估，升级为基于真实步行路网耗时的可达性分析：自动生成 15 分钟步行等时圈，统计基础医疗、小学、菜市场、药店、购物/超市、养老服务等民生设施覆盖，识别 1 km 服务盲区，并输出可复核、可导出的社区体检成果。

项目采用轻量 Web 架构，不依赖 GPU，不要求获取百度底层道路拓扑，普通电脑即可本地运行。

---

## 2. 为什么要做这个项目

“15 分钟生活圈”的关键不是“直线距离够不够近”，而是**居民是否真的能在限定时间内走到**。

现实步行可达性会受到道路绕行、河道、围墙、路口、桥梁、过街设施和建筑出入口等因素影响。若只在地图上画一个固定半径圆，可能把实际不可达区域误判为可达，也可能掩盖公共服务的真实缺口。

圈析智图围绕三个问题展开：

1. **真实可达性**：15 分钟究竟能走到哪里？
2. **设施覆盖**：可达区域内已有多少民生设施？
3. **服务盲区**：哪些位置仍缺少菜市场、药店或小学等关键服务？

## 3. 产品工作流

```text
输入地址 / 中心坐标
        ↓
坐标标准化（BD09LL）
        ↓
多方向 × 多半径扇形采样
        ↓
RouteMatrix Walking 批量步行测时
        ↓

        ↓

        ↓
Place 多类别 / 多页 POI 检索与去重
        ↓

        ↓
路网差异诊断 + 数据置信度 + 规划建议
        ↓
真实城市 3D / 数字孪生表达 / 分析热力图
        ↓
Markdown / HTML / CSV / JSON / GeoJSON / ZIP 导出
```

## 4. 核心能力

### 4.1 真实路网 15 分钟等时圈

系统默认在中心点周边设置 **16 个方向 × 4 个半径**，形成 64 条步行路线探针。通过百度 RouteMatrix Walking 批量获取真实步行距离与耗时。

RouteMatrix 单批路线数受平台上限约束，项目会自动拆批，例如默认 64 条路线拆为 **50 + 14**。系统同时分别记录 HTTP 请求次数和路线配额单元估算，不把“减少网络请求”误宣传成“减少路线配额”。

### 4.2 稳定的阈值插值

真实地图绑路偶尔会产生局部非单调现象，例如更远的采样点反而返回更短耗时。若直接插值会产生边界尖刺。

系统先在单一方向上构造**保守单调耗时包络**，再寻找 900 秒阈值并进行径向插值，同时公开展示“单调纠正次数、有效方向、边界截断、近中心外推”等质量诊断指标。

### 4.3 多类别 POI 覆盖

系统检索：

- 基础医疗
- 小学
- 菜市场
- 药店
- 购物 / 超市
- 养老服务

Place 检索支持多页读取和去重。只有真正落入等时圈的设施才计入“15 分钟可达覆盖”。

### 4.4 服务盲区识别

根据命题任务书要求，系统在等时圈内部构造采样点，对每个点检查 **1 km 内是否存在菜市场、药店或小学**。

若缺失任一关键类别，则标记为服务盲区采样点；多类别同时缺失时提高严重度。

若某一关键 POI 类别因网络、配额或 API 异常而无法确认，系统标记为 `unknown / 待核验`，不会把“接口失败”误写成“现实中没有设施”。

## 5. 空间可视化：既追求冲击力，也区分真实性

为避免“漂亮但不可验证”，项目将视觉层分成三种：

### 5.1 真实城市 3D

配置独立浏览器端百度地图 AK 后，通过官方异步回调方式加载 **百度 JSAPI GL WebGL** 城市底图。采用高缩放级别、倾斜与旋转视角展示真实城市空间，并叠加：

- 15 分钟等时圈
- 500 m / 1 km 距离参考圈
- POI
- 服务盲区
- 路网耗时探针

支持自动环绕、实时路况、卫星底图和重置视角。可选配置百度个性化地图 `Style ID` 进一步提升答辩展示效果。

> 真实城市建筑的精细程度取决于百度地图在目标区域的三维底图覆盖与当前缩放级别。

### 5.2 数字孪生表达

在没有浏览器地图 AK 时，仍可根据分析结果生成楼体、道路、树木、等时圈、POI 与盲区的 2.5D / 3D 表达层。

该视图只用于**空间关系表达和离线演示**，明确标注不是实际 BIM / 地籍楼块。

### 5.3 分析热力图

保留算法友好的平面热力图，用于解释：

- 各采样点步行耗时
- 等时圈边界
- POI 分布
- 服务盲区

视觉冲击和技术可解释性分别承担不同职责。

## 6. 工程优化与可靠性

### 6.1 批量与并发

- RouteMatrix 自动批量拆分；
- POI 类别有界并发；
- `BAIDU_CONCURRENCY` 可按真实 QPS 调整；免费账户正式默认值为 1。

### 6.2 缓存

- 进程内缓存；
- SQLite TTL 持久缓存；
- 相同近期请求可复用，减少重复 QPS 与配额消耗。

### 6.3 容错

- HTTP timeout；
- 有界重试与指数退避；
- POI 类别独立失败；
- 关键 RouteMatrix 失败时拒绝生成假等时圈；
- 代表路线失败不阻断主分析；
- 数据置信度明确展示。

### 6.4 密钥安全

服务端 `BAIDU_MAP_AK` 只在后端读取，不返回浏览器、日志和导出文件。

浏览器地图使用**独立的** `BAIDU_MAP_BROWSER_AK`，这是 JSAPI 客户端正常需要公开的凭证，应在百度控制台配置 Referer 白名单，不能与服务端 AK 混用。

## 7. 路网价值的量化证明

项目不仅画出等时圈，还量化“直线圆为什么会失真”：

- 直线步行基线半径
- 直线圆面积
- 等时圈 / 直线圆面积比
- 路径绕行系数中位数
- 实际耗时 / 直线理论耗时比

这样评委可以直接看到真实路网带来的空间差异，而不是只看一张漂亮地图。

## 11. 主要创新点

### 创新一：无需底层道路图的 API 测时等时圈

把地图平台视为“真实路网函数”，通过稀疏测时 + 空间插值逼近连通可达区域，降低 GIS 工程门槛。

### 创新二：同时量化结果与可信度

不只给结果，还给有效样本率、纠正次数、边界截断和数据置信度，让评委能判断结果质量。

### 创新三：`unknown` 不等于 `0`

数据源失败时拒绝输出确定性缺失结论，避免规划工具最危险的一类错误。

### 创新四：真实城市 WebGL + 算法解释双层可视化

真实地图负责城市空间感，热力分析负责算法解释；数字孪生表达负责离线展示，三者职责清晰。

### 创新五：从分析到结构化成果交付

结果可导出 CSV / JSON / GeoJSON / ZIP，具备继续集成和复核能力。

### 创新六：证据约束的 AI 解读

可选模型只接收后端筛选后的分数、覆盖、盲区、质量诊断和确定性建议，不接收 AK、POI 名称或中心坐标，也不改写地图事实。它将结构化结果转换为便于规划沟通的中文摘要，核心计算在模型不可用时仍完整运行。

## 13. 项目边界

圈析智图是**规划筛查和辅助分析工具**，不替代政府正式规划审批。

当前版本未接入人口密度、设施容量、土地权属、无障碍设施、政策红线、实时施工围挡等全部城市治理数据，因此输出应作为进一步现场调研和规划论证的线索，而不是最终行政结论。
