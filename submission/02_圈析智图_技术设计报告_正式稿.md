# 圈析智图（LifeCircle Insight）技术设计报告
## 基于地图开放能力的“15 分钟生活圈”智能体检与规划助手

**版本：** v3.0.0-rc3  
**开源许可证：** MIT  
**测试状态：** v3.0.0-rc3 已在 Windows 完成 35 项自动化测试、真实百度 API、真实三维底图、模型解读、七类导出和两社区 A/B 验收。

---

## 摘要

圈析智图以百度地图开放能力为核心空间计算引擎，在不持有底层道路拓扑的前提下，通过多方向多半径扇形采样、RouteMatrix Walking 批量步行测时、保守单调包络与阈值插值，构建近似 15 分钟步行等时圈；结合 Place 多类别 POI、1 km 服务盲区识别、路网差异指标、算法质量诊断、真实 WebGL 城市地图与多格式导出，形成一套普通电脑即可运行的社区生活圈体检工具。

本项目的设计原则是：**地图事实由地图 API 和确定性算法产生，未知数据明确标记，展示层不冒充数据层。**

---

## 1. 需求映射

命题要求主要包括：

1. 地图 API 坐标转换、POI、路径规划 / 距离能力；
2. 基于真实路网计算 15 分钟步行等时圈；
3. 统计民生设施覆盖；
4. 识别周边 1 km 内缺少菜市场、药店或小学的服务盲区；
5. 对大量 POI / 路线合理批量或并发；
6. API 异常和限流下具备容错；
7. 可视化、交互和开源工程规范；
8. 技术报告和真实社区对比测试。

项目逐项实现，并将评分证据映射记录在 `docs/评分点逐项对照表.md`。

## 3. 坐标与数据边界

### 3.1 内部坐标

分析内部统一使用 **BD09LL**。

- BD09LL 输入直接使用；
- GCJ02 / WGS84 输入通过百度坐标转换服务标准化；
- 地址输入使用地理编码转为中心点坐标。

### 3.2 真实与模拟严格分离

- `demo`：只使用仓库中明确标注的模拟路网 / POI 数据；
- `real`：真实调用百度地图 Web 服务 API；
- 浏览器真实城市地图可以单独加载，但如果分析仍为 `demo`，页面必须明确声明“底图真实、分析数据模拟”。

## 4. 等时圈生成算法

### 4.1 扇形探针

默认参数：

- 方位数 `B = 16`
- 半径：`500 / 900 / 1300 / 1700 m`
- 路线数：`16 × 4 = 64`
- 阈值：`15 min = 900 s`

每个候选点由中心点根据方位角与半径计算得到，然后批量送入 RouteMatrix Walking。

### 4.2 RouteMatrix 批量策略

根据平台批量能力，默认 64 条路线自动拆批。例如每批最多 50 条时：

```text
64 OD routes
  -> batch 1: 50
  -> batch 2: 14
```

系统分别统计：

- HTTP 请求数；
- `quota_units_estimated` 路线单元估算；

避免把“2 个 HTTP 请求”误解释成“只使用 2 条路线配额”。

### 4.3 有效样本检查

若 RouteMatrix 成功样本比例低于安全阈值，主分析应终止，而不是利用大量缺失数据拼接假边界。

### 4.4 保守单调包络

单一方向上，理论上半径越大，步行耗时应整体非减。但实际 API 可能由于道路入口、绑路和端点位置出现局部非单调：

```text
r1 < r2, 但 t(r1) > t(r2)
```

项目采用：

```text
t'_i = max(t_1, t_2, ..., t_i)
```

构造累计最大耗时包络，再进行阈值搜索。

所有纠正次数均保留到 `isochrone_diagnostics` 中，不静默隐藏异常。

### 4.5 阈值插值

若 900 秒位于两个样点 `(r1,t1)` 与 `(r2,t2)` 之间，则按径向线性插值：

```text
r* = r1 + (900 - t1) / (t2 - t1) × (r2 - r1)
```

各方向得到边界半径后，按方位连接为近似等时圈 Polygon。

该方法属于**API 测时 + 空间插值**，不是底层路网洪泛搜索，因此项目不声称获得精确道路拓扑等时面。

## 5. POI 检索与清洗

六类设施独立检索：基础医疗、小学、菜市场、药店、购物 / 超市、养老服务。

主要清洗过程：

1. 多页分页；
2. 严格半径；
3. UID 优先去重；
4. 名称 + 坐标补充去重；
5. 坐标统一；
6. 类别归一化；
7. 距离缺失时仅用地理距离补充展示值；
8. 类别 API 失败标记为 `unknown`。

只有落入最终等时圈 Polygon 的 POI 才计入 15 分钟覆盖统计。

---

## 6. 服务盲区识别

在中心周边构造候选网格，只保留位于等时圈内的采样点。

对每个点检查关键三类服务：

- 菜市场
- 药店
- 小学

若 1 km 内不存在某一类别，则记录缺失；严重度等于缺失类别数。

### 6.1 数据不完整保护

若关键三类中任意一类 API 本次状态为未知，则：

- 不把该类记为 0；
- 不输出确定性“服务盲区”结论；
- 页面和导出报告显示待核验。

这是规划分析中的重要可靠性约束。

## 7. 真实路网价值指标

### 7.1 直线基线

内部采用可配置基线步行速度 `BASELINE_WALK_SPEED_MPS`，默认 1.2 m/s，仅用于方法对比。

```text
naive_radius = threshold_seconds × baseline_speed
```

计算直线圆面积后，与真实路网等时圈进行比较。

### 7.2 诊断指标

- `isochrone_to_naive_area_ratio`
- `median_route_detour_ratio`
- `median_time_penalty_ratio`

这些指标用于解释真实路网对可达性的影响，不作为政府正式生活圈评价标准。

## 8. 三层空间可视化设计

### 8.1 真实城市 3D

使用独立浏览器 AK，通过官方异步回调加载百度 JSAPI GL WebGL 地图：

- 高缩放级别；
- 倾斜 `tilt`；
- 旋转 `heading`；
- 可选个性化地图 Style ID；
- 500 m / 1 km 距离参考圈；
- 15min 等时圈；
- POI、盲区、路网测时探针；
- 自动环绕 / 实时路况 / 卫星底图。

底图建筑精模或三维楼块的显示由百度地图该区域的数据覆盖、缩放级别和客户端能力决定。

### 8.2 数字孪生表达层

Canvas 依据分析结果生成道路、楼体、绿化、POI 和盲区，保证无浏览器 AK 时仍能进行视觉演示。

它不是实际 BIM / 建筑地籍数据，界面明确标注真实性边界。

### 8.3 分析热力图

SVG 视图承担算法解释，突出：

- 采样耗时等级；
- 15min 边界；
- 设施点；
- 盲区点。

三层视图避免用“炫酷地图”替代技术证据。

## 9. 容错、缓存与配额控制

### 9.1 HTTP 容错

- timeout；
- 有界重试；
- 指数退避；
- 安全错误摘要；
- 不记录完整 AK。

### 9.2 功能级降级

- POI 某类别失败：该类别 unknown，其他类别继续；
- DirectionLite 失败：不影响主等时圈；
- RouteMatrix 关键失败：终止主分析；
- 静态图失败：不影响结构化结果。

### 9.3 缓存

相同 GET 请求支持内存与 SQLite TTL 缓存，以减少重复 QPS 和真实接口耗时。

## 10. 安全设计

### 10.1 服务端 AK

`BAIDU_MAP_AK`：

- 只由 FastAPI 读取；
- 不返回 `/api/config/status`；
- 不写入前端；
- 不写入导出文件；
- 日志禁止输出完整密钥。

### 10.2 浏览器 AK

`BAIDU_MAP_BROWSER_AK` 用于 JSAPI GL，本质上会随网页发送至浏览器，因此必须：

- 单独创建浏览器类型应用；
- 配置 Referer 白名单；
- 不与服务端 AK 复用。

`BAIDU_MAP_STYLE_ID` 仅是可选地图样式标识，不承担服务端鉴权。

## 15. 真实 A/B Benchmark

2026-09-14 使用两个上海街道级样例完成一次同参数真实运行：


- 日期；

| 指标 | 张江镇街道级样例 | 徐家汇街道级样例 |

| 等时圈面积 km² | 1.608 | 2.088 |

## 16. 证据约束的模型解读

模型能力是结果解释层，不是空间事实层。后端只发送模式、区域名、分数、覆盖、盲区、对比指标、质量诊断、确定性建议与警告；主动排除 AK、坐标、POI 名称和 API 调用明细。模型必须标注模拟数据、不得改变分数或虚构设施，失败时核心分析和导出不受影响。调用由用户手动触发，并通过服务端 OpenAI 兼容接口完成。

---

## 17. 已知边界

1. 等时圈是离散路网测时后的空间插值近似，不是底层道路图洪泛结果；
2. POI 数据代表地图平台当前检索结果，不代表设施容量、质量和实时营业状态；
3. 未接入口径统一的人口、土地、政策和现场障碍数据；
4. 浏览器三维底图的建筑精细程度受百度地图区域数据覆盖影响；
5. 本工具用于快速筛查和辅助决策，不替代正式规划审批。

---

## 18. 结论

圈析智图的核心价值不在于“再做一个地图页面”，而在于把真实步行路网 API、可解释空间插值、设施覆盖、服务盲区、工程可靠性和结构化交付组合成一个可部署、可复现、可审计的开源工具。

正式提交前剩余工作集中在**团队身份字段、公开仓库和演示视频链接**，不再需要重写主体架构或重复消耗地图 API 配额。
